# Run 2 结果计算与判读（多轮累计法）

> 数据来源：`raw_data/run2_测量记录表.csv`（2026-11-12 20:50 起，2026-11-13 14:41 止）。
> 本文件只做计算与判读，不改动原始记录。

## 一、两轮原始数据

| 轮次 | 起止 | 起始电量 | 结束电量 | 时长 | 灯数变化 |
|---|---|---|---|---|---|
| 1 | 11-12 20:50 → 23:40 | 21% | 100% | 170 min | 4 → 2 |
| 2 | 11-13 12:40 → 14:41 | 25% | 83%（表）/ 84%（照片 14:48） | 121 min | 2 → 0（末灯闪烁后熄灭） |

第 2 轮的结束判据是**指示灯由闪烁转为不亮**：本人回忆熄灭时刻约 14:41，14:50 采样记到 0 灯。14:48 的照片（`photos_run2/run2_04_耗尽状态_1448_84pct_1灯闪烁.jpg`）显示当时手机 **84%**、最后一颗指示灯**仍亮且处于闪烁状态**——照片截到的是「低电告警闪烁」的亮相，不是熄灭后的状态。

因此准确表述是：**充电宝已放电至自动关断（末灯闪烁后熄灭），实验按预注册规则结束**，未做第 3 轮。关断的分钟级时刻只有人眼观察，不是仪器判据（见第六节局限 3、4）。

## 二、能量计算

手机电池能量 23.34 Wh（6000 mAh × 3.89 V，出厂规格）；充电宝电芯 37 Wh（10000 mAh × 3.7 V，铭牌）。

| 轮次 | 电量差 | 充入手机能量 |
|---|---|---|
| 1 | 100% − 21% = 79% | 0.79 × 23.34 = **18.44 Wh** |
| 2 | 83% − 25% = 58% | 0.58 × 23.34 = **13.54 Wh** |
| 合计 | 137% | **31.98 Wh** |

表面效率：

```
η_表面 = 31.98 / 37 = 86.4%
```

折合：**一次满电充电宝，可向本机注入 1.37 个手机电池当量。**

## 三、这个 86.4% 不能作为结论

铭牌给出的链路是：37 Wh 电芯 → 30 Wh @5V 输出（转换率 81.1%）→ 再经手机充电电路。

**81.1% 只是电芯到 5V 输出这一段。** 5V 到电池还要经过手机内部的降压/升压与充电管理，典型效率 85%~90%。所以端到端的物理上限约为：

```
0.811 × 0.85 ~ 0.90 = 69% ~ 73%
```

对应能量 25.5~27.0 Wh，折合手机电池 1.09~1.16 次。

**实测 31.98 Wh 比这个上限高 18%~25%，超出任何测量误差可以解释的范围。** 因此 86.4% 不是效率值，而是一个**被高估的计算结果**。

这一点与 Run 1 的 93.4% 属于同一类错误，只是规模不同：

| | Run 1 | Run 2 |
|---|---|---|
| 分子来源 | 0.58 次 × 2290 mAh，粗估 | 电量差 × 23.34 Wh，确定值 |
| 分母来源 | 灯数折算 3/4 颗灯 = 27.75 Wh | 铭牌 37 Wh，确定值 |
| 结果 | 93.4%（比铭牌升压效率 81.1% 还高，物理不可能） | 86.4%（比端到端上限 73% 高约 13~17 个百分点） |
| 矛盾程度 | 严重 | 显著，但已缩小 |

**多轮累计法确实消掉了分母的估算**（不再用灯数折算），**但分子仍然建立在手机电量百分比上**，而百分比是 BMS 的估计值，不是电量刻度。换掉一个不确定量，引入了另一个不确定量——这是本次实验最需要说清楚的一点。

## 四、两个竞争性解释（当前数据无法区分）

| 假设 | 内容 | 若成立，实测值会 | 如何判别 |
|---|---|---|---|
| H1 | 手机电量百分比在高 SoC 段非线性，1 个百分点对应的能量高于平均值，导致分子被高估 | 偏大 | 用 USB 功率计直接对功率积分，不依赖百分比 |
| H2 | 充电宝电芯实际容量高于标称 10000 mAh（该型号常见实测 10500~11000 mAh，即 39~41 Wh），导致分母偏小 | 偏小（真实 η 更低） | 用电子负载恒流放电至截止，积分容量 |

两者都能解释 18%~25% 的超额，**现有数据不足以在两者之间裁决**。若 H2 成立（电芯实际 40 Wh），则 η = 31.98/40 = 80.0%，与铭牌 81.1% 吻合。

## 五、能站住的结论（不依赖效率数值）

1. **充电宝确实能从满电用到自动关断，完整跑完一个循环。** 这是 Run 1 做不到的——Run 1 在手机充满时就停了，充电宝还剩 1 灯，从未真正放空。末灯闪烁、随后熄灭的过程有 14:48 的现场照片，是 Run 1 没有的证据类型。
2. **一次满电注入 1.37 个手机电池当量（上限值）。** 若百分比高估（H1），真值只会更低。铭牌推算为 1.09~1.16 次，两者同量级。
3. **没有发现虚标迹象。** 实测值偏向"充电宝表现优于铭牌"，而不是"达不到铭牌"。这与此前 Run 1 得出的"93.4%"给读者的印象方向相反。
4. **指示灯不可用于容量折算。** 第 1 轮灯数从 4 掉到 2（一半），实际只消耗了电芯的 40%~50%；第 2 轮灯数 2→0 消耗了剩余全部。灯是电压阈值，不是电量刻度。这一点由本组数据直接证伪了 Run 1 的折算方法。

## 六、局限（必须随结论一起出现）

1. **百分比分辨率不足**：1 个百分点 ≈ 0.23 Wh，两轮读数各 ±1 个百分点即 ±0.5 Wh，占比 1.5%，不足以解释 18% 的偏差，但也不为零。
2. **第 1 轮结束照片未拍**（见 `run2_照片缺失记录.md`），该节点影像证据缺失；第 2 轮的耗尽状态**有照片**（14:48，84%，末灯闪烁），这是 Run 1 完全缺失的证据类型。
3. **第 2 轮结束电量取 83%（照片为 84%）**：14:40 读数 83%，14:48 照片 84%。计算取较低的 83%，因此 13.54 Wh 与 31.98 Wh 是**下限值**，真实值约高 0.23 Wh（0.7%），不改变任何结论方向；但由于结论是"实测超出物理上限"，取下限已是偏严的算法。
4. **「关断」是人眼判据，不是仪表判据**：灯在闪烁，14:50 记的 0 灯是闪烁间隙的观察，而 14:48 的照片仍拍到末灯亮着。关断时刻只有分钟级可信度，能量计算不依赖该时刻，时长与平均功率均为近似值。
5. **未使用外部仪器**（功率计 / 电子负载），全部依赖设备自带显示。

## 七、下一步（若继续）

1. 串一个 USB 功率计，直接对功率积分得到真实输出能量，取代"电量差 × 电池容量"。
2. 用电子负载对充电宝做 1A 恒流放电，测实际可用容量，判定 H2。
3. 两者任一完成，即可给出可信的效率值；在此之前，本文只报"次数"与"上限"，不报效率。
