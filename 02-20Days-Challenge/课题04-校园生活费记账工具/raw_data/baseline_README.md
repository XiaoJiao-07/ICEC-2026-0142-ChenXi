# 10-15 ~ 10-22 消费基线说明

> 本文由本人提供事实，AI 协助整理文字。凡标「待补」处，将在补齐后由本人确认，不做替代。

## 一、数据是什么

本人 2026-10-15 ~ 10-22 的真实消费，共 **39 笔**，日均约 40 元，见 `baseline_2026-10.csv`。
内容真实——每一笔钱都真实花过。

## 二、原始记录载体（关键）

- **载体**：手机备忘录。
- **方式**：当天花完钱就记一条，写金额和用途（如「3 早餐」「13 午饭」），不是固定时间记，一天可能记三四条，也可能只记一条。
- **结论**：这批记录**是逐日发生的**，只是它一直存在手机里，从未以文件形式进入仓库。

这就是本文件要澄清的核心区别：**记录发生在逐日，但入库方式是一次性的。**

## 三、入库方式（问题所在）

2026-10-22，为了提交阶段二材料，我把备忘录里的 39 笔一次性整理出来，通过 AI 协助写成 `main.js` 中的 `SEED_DATA` 常量，同日导出为 CSV。

- 造成的结果：数据以「源码常量」形式出现在仓库里，读者看到的是「一堆数字」，而不是「一段逐日记录的过程」；
- 行为定性：**入库方式不合规**（事后一次性整理），而非数据内容不真实；
- 已整改：2026-11-09 起 `SEED_DATA` 已从源码移除，数据独立为 CSV；程序改用文件存储，逐笔写入 `data/expenses.json`。

## 四、边界声明

这 39 笔是**消费数据**，不是**程序运行日志**。因此：

- 可作为个人消费基线、可作为需求来源（例如"日均 40 元"这类结论）；
- **不计入**「连续 ≥7 天程序自动化运行日志（Telemetry）」评分项——那一项只能由 2026-11-09 起的真实运行时日志承担。
