# 用户测试采集方法说明

> 这份文件不是成果，是**方法声明**。写在前面的目的，是让任何一位评审在看到 8 份用户数据时，先知道它是怎么来的、哪里不完美，而不是自己去猜。

## 一、设备条件（主动披露）

**全部用户的首次试用，都在同一台笔记本（项目作者本人的 Windows 电脑）上完成。**

原因很直接：作者只有这一台可用的电脑；受访者是同宿舍、同班的同学，走到桌前试用 3 分钟，是唯一现实可行的方式。

**这不是理想条件，所以先写在这里。** 与其让评审在日志里发现"8 份数据的环境痕迹完全一致"，不如自己先说清楚——前者是隐瞒，后者是交代。

## 二、一台设备上，怎么区分 8 个人（技术手段）

| 手段 | 说明 |
|---|---|
| **一人一副本** | `用户测试-01` … `-08`，各自独立的 `process_logs/` 与 `data/`，互不覆盖 |
| **副本使用前清空** | 每份副本在交给下一个人之前，清掉 `process_logs/*.log` 与 `data/expenses.json`，保证"第一行日志"一定是该用户产生的 |
| **独立哈希链** | 每份副本的链都从 `seq=1, prev_hash=GENESIS` 起算。**一条从 GENESIS 开始的链，只能证明一件事：这是该副本的第一次运行** |
| **操作节奏差异** | 日志含毫秒时间戳、`elapsed_ms`、完整操作序列。不同用户的输错方式、停顿长度、是否填备注，天然不同（见下例） |

**已有的实证例子**（同一天、同一台机器、两个不同的人）：

| | U1 | U2 |
|---|---|---|
| 启动时刻 | 21:39:13.748 | 21:43:48.267 |
| 第一次输入 | `23` | `早餐0，午餐13，晚餐17` |
| 后续行为 | 被提示后重开程序，走完四步，记成 1 笔 | 按 `2` 看到空列表后**停手** |
| 结果 | 1 笔，7 分 53 秒 | 0 笔，约 1 分钟 |

两个人、同一台机器、相差 4 分钟，行为完全不像同一个人。这类差异不是设计出来的，是记录出来的。

**第三个例子（2026-11-14，界面已中文化）**：U3 在 54 秒内自行走完四步、记成 1 笔，并主动按 `2` 复查。

| | U1 | U2 | U3 |
|---|---|---|---|
| 关系 | 室友 | 室友 | **同班（不同宿舍）** |
| 界面 | 英文 | 英文 | **中文 v2.4** |
| 启动→记账 | 7 分 53 秒 | 未完成 | **54 秒** |
| 类别 | 午饭记成"交通" | — | 选对"餐饮" |
| 是否被提示 | 被提示"按 1" | 未被提示 | 未被提示 |

同一台机器、同一套流程，三种行为、三种结果。**如果是一个人分饰三角，最不可能变的就是"用时"和"是否选对类别"这两列。**

**一项已确认的补充（2026-11-14 22:39，作者本人回答）**：三人**都没有旁观过彼此操作**——「我找的人都没看过」。U3 是同班、不同宿舍，来之前没见过这个程序，54 秒是他第一次上手的时间。这条排除了"后面的人在旁边学会了再上手"这一最容易被质疑的污染路径。


## 三、如何补足"人的痕迹"（设备之外的部分）

同一台设备无法改变，但"是谁在用"可以由以下四样补足，**缺一样不计入**：

1. **日期**——哪天第一次用
2. **他自己的屏幕截图**——带任务栏时间
3. **他本人的原话**——逐字记录，不改写、不归纳
4. **遥测日志**——从 GENESIS 开始的那条链

**加分项（不强制）**：现场照一张，画面含操作者的手、屏幕、宿舍背景，不拍脸。这张能直接回答"是不是另一个人坐在那儿"。

**已落实**：U3（2026-11-14）拍摄了现场照 `2026-11-14_U3_3_现场照_手与屏幕.jpg`——画面里有操作者的手、屏幕上的程序界面、桌面环境。这是三次测试中的第一张，后续每位补一张。

## 四、已知局限（不隐瞒、不淡化）

| 局限 | 影响 | 处理 |
|---|---|---|
| 同一台设备 | 运行环境痕迹同源（同一 `node.exe`、同一路径） | 无法消除，只能用第一、二节说明 |
| 受访者集中在同宿舍、同班 | 样本代表性有限，不能外推到全校 | 报告中限定结论范围 |
| 均为一次性试用 | 不能证明留存意愿、不能证明长期可用性 | 不把"愿意继续用"写进结论；**U3 已明确「明天不会用」，3 人中 0 人表示愿意继续** |
| **受访者多为「平时不记账」的人** | **测出来的是"不记账的人会不会用记账工具"，不是"记账的人用得爽不爽"** | **剩 5 位中刻意找 1–2 位本来就在记账的人（微信记账本/Excel/纸条/支付宝账单都算），记录卡增加一栏"他平时用什么记"** |
| 存在同一晚连续试用 | 时间分布集中 | 后续用户尽量分散到不同日期 |

## 五、后续改进（正在执行）

- [ ] 后续用户分散到不同日期，不再一晚连续多人
- [ ] **剩 5 位中至少 1–2 位是"本来就在记账"的人**（微信记账本 / Excel / 纸条 / 支付宝账单截图），否则 8 人全是"不记账的人"，结论只能写成"给不记账的人做记账工具"
- [ ] 记录卡增加一栏：**他平时用什么记账？**（原卡只问了"平时怎么记账"，答案"平时不记账"就已足够，但需要提前知道，否则白白浪费一位用户）
- [ ] **至少 2–3 人把便携包拷回自己电脑使用**（U 盘或 QQ 传，不用微信，`node.exe` 有 99MB），形成异机证据
- [x] 每人的 `process_logs` 当场拷出，命名 `YYYY-MM-DD_U{n}_telemetry.log`（U1/U2/U3 均已执行）
- [ ] 每人补一张现场照（手 + 屏幕）——**已 1/3**（U3 有，U1/U2 当晚未拍，不补拍，如实记为缺）

## 六、判断标准：什么算一个"真实用户"

**四项齐备即计入**：日期 / 本人屏幕截图 / 本人原话 / 本人用过（有从 GENESIS 开始的遥测日志）。

**不要求记账成功。** U2 记了 0 笔，四项齐备，计入，并如实标注「尝试后放弃」。

理由：考核要的是"8 位真实用户"，不是"8 位成功记账的用户"。**一个被第一步劝退的人，比一个被手把手带着做完的人，暴露的问题更多。**
