# 用户测试采集方法说明

> 这份文件不是成果，是**方法声明**。写在前面的目的，是让任何一位读到这 8 份用户数据的人，先知道它是怎么来的、哪里不完美，而不是自己去猜。

## 一、设备条件（主动披露）

**全部用户的首次试用，都在同一台笔记本（项目作者本人的 Windows 电脑）上完成。**

原因很直接：作者只有这一台可用的电脑；受访者是同宿舍、同班的同学，走到桌前试用 3 分钟，是唯一现实可行的方式。

**这不是理想条件，所以先写在这里。** 与其让别人在日志里发现"8 份数据的环境痕迹完全一致"，不如自己先说清楚——前者是隐瞒，后者是交代。

**副本存放位置（2026-11-15 18:21 变更，如实记录）**：`用户测试-01`～`05` 已从桌面根目录移入 `桌面\_证据副本_勿动\`，**内容一个字节未改，只换了位置**。原因：U4 测试时桌面同时摆着 5 个同名副本，他问了一句「点那个」，无法判断他是在问"进哪个文件夹"还是"点哪个文件"（见 `2026-11-15_U4.md` 3.2）。移入归档后，桌面只留待用的那一份，下一轮可测准。该文件夹内附 `说明_勿删.txt`，含副本与用户的对照表。

## 二、一台设备上，怎么区分 8 个人（技术手段）

| 手段 | 说明 |
|---|---|
| **一人一副本** | `用户测试-01` … `-08`，各自独立的 `process_logs/` 与 `data/`，互不覆盖 |
| **副本使用前清空** | 每份副本在交给下一个人之前，清掉 `process_logs/*.log` 与 `data/expenses.json`，保证"第一行日志"一定是该用户产生的 |
| **独立哈希链** | 每份副本的链都从 `seq=1, prev_hash=GENESIS` 起算。**一条从 GENESIS 开始的链，只能证明一件事：这是该副本的第一次运行** |
| **操作节奏差异** | 日志含毫秒时间戳、`elapsed_ms`、完整操作序列。不同用户的输错方式、停顿长度、是否填备注，天然不同（见下例） |

**已有的实证例子**（同一天、同一台机器、两个不同的人）：

| | U1 | U2 |
|---|---|---|
| 启动时刻 | 21:39:13.748 | 21:43:48.267 |
| 第一次输入 | `23` | `早餐0，午餐13，晚餐17` |
| 后续行为 | 被提示后重开程序，走完四步，记成 1 笔 | 按 `2` 看到空列表后**停手** |
| 结果 | 1 笔，7 分 53 秒 | 0 笔，约 1 分钟 |

两个人、同一台机器、相差 4 分钟，行为完全不像同一个人。这类差异不是设计出来的，是记录出来的。

**第三个例子（2026-11-14，界面已中文化）**：U3 在 54 秒内自行走完四步、记成 1 笔，并主动按 `2` 复查。

八个人、同一台机器、同一套流程，**八种行为、八种结果**。**如果是一个人分饰八角，最不可能变的就是"用时""启动次数""是否输错""记完的收尾"这四列**——而这几列恰好都是遥测或当场勾选写下来的，不是事后回忆的。

**第八个例子（2026-11-22，ITER-005 第 2 位验证）**：U8 用 **11.9 秒**记成 1 笔 15 元，是 8 位里第二快。**他在合计行之后问了「这样就行了是不是」，然后起身走了——程序没关。**

这一位补上了 U7 缺的那一块——**记录卡 H 格第一次填全：「手指停了」**。也就是说，那行「按 2 可核对，按 1 再记一笔」确实被他读懂了一瞬。

但收尾动作在当天 13:19 被**进程证据**改了：归档副本时 `mv` 报「文件被占用」，查出 U8 那次的 `node.exe`（13:05:56 启动，与遥测第一行同一秒）**一直活着**，配套的 `cmd.exe` 也还在跑。而 `app.js` 里按 `0` 必走 `process.exit(0)`——**他没按 0**。他记完就离开了，程序停在菜单上开着，直到 13 分钟后被发现并结束。

| | U7 | U8 |
|---|---|---|
| 看见合计行 | 扫一眼就走 | 扫一眼就走 |
| 手指停了吗 | 没看清 | **停了半秒以上** |
| 之后 | 坐着不动 | **起身走了，窗口留着** |
| 按 2 核对 | 没有 | 没有 |
| 按 0 退出 | 没有 | **没有（进程存活证明）** |

**两个人，同一件事的两种形态：程序告诉了他「记上了」，没告诉他「可以走了」。** 于是 U7 留在原地等，U8 干脆走掉、把程序留在菜单上——**程序给了两个键，两个人一个都没按。**

这也顺手说明一件事：**记录卡上「按 0」是模板预设的**（G 格选项直接写「完全没看，直接按 0」），填卡的人顺着填了。**要判断「他到底做了什么」，进程和日志比勾选可靠。**

**U8 的三问是事后补的（13:14，作者转述）**，要按事后回忆的权重记：最别扭答「**没有最别扭，都差不多**」、明天「**不用**」、平时「**用微信**」。其中「没有最别扭」是 8 人里第一次有人答「没有」——**这条只记录、不进结论**，因为同一天 U7 在同一版本上明确答「入口」，两条互相抵消，而第 9 位已经没有了。

**唯一能进结论的是留存**：U3、U7、U8 三位明确说不会再用，**且三位都记成了（36 / 13 / 15 元），最快的 U8 只用了 11.9 秒**。它不是「用不动」，是「用不着」。

**第六个例子（2026-11-18，ITER-004 修复后）**：U6 用 21.7 秒记成 1 笔 17 元，遥测仍只有 2 行。三问里"最别扭"答的是「**记的过程**」——入口改造之后，别扭的位置第一次被指到了门内。而他在按 `1` 之前还问了作者一句，**同一个位置的两层证据**。

**第七个例子（2026-11-21，ITER-005 确认语上线后）**：U7 用 30.6 秒记成 1 笔 13 元，账本 1 笔、无重复。**程序确实多印了一行「今天已记 1 笔，合计 13.00 元」，他看完之后仍然问了「这样就行了吗」，然后坐着不动。** 时序已由作者确认（「合计之后问的」），所以这次不需要再打问号：**改动生效了，问题没解决。**

这是全份材料里最有价值的一次对照，原因在于它同时否掉了两个常见做法：

| 常见做法 | 本轮实测 |
|---|---|
| 「多印一行合计，用户就知道记上了」 | 合计印出来了，他仍问「这样就行了吗」 |
| 「再告诉用户下一步按 2 / 按 1」 | 那一行也印了，他仍坐着不动 |

**能救的只有半条：他没关掉重开（1 次启动）。** 而 U4 当年正是因为不信，关掉重开了 3 次——**同一处修改，把「重开」按住了，没把「问」按住。**

他还有一处与前六位都不同：**第一次双击的是 `使用说明.txt`**，不是启动脚本。这是改造后第一次出现误点，`ITER-003` 的「改动后 0 人点错」这个数已按事实改为「4 人里 3 人命中」。但误点的后果变了——**从「点到会闪退的 exe」变成「打开记事本、什么都没坏」**，代价是 30 秒，不是卡死。

**而且那 30 秒不是用来读说明的**——作者答复原文「使用说明.txt 之后没读」。他打开、没读、自己在 30 秒内找到了 `①双击我记账.bat`。**「写一份说明放在旁边」这个做法，被一次真实行为否掉了。**

**一条关于"证据落地"的方法记录（2026-11-18）**：U6 的记录卡第一次交上来时只有后半页截图，且文件未保存（磁盘上仍是空白模板、4078 字节），**六项关键信息一度全部缺失**。22:21 作者保存后（4299 字节）才补全，其中包含一句「**这样就行了吗**」——P13 的第一条直接言语证据（11-21 U7 是第二条，一字不差地重复了同一句）。**教训写进流程**：记录卡的关键六项必须放在文档最前，填完先按 Ctrl+S，再截图。已落实在 `记录卡模板_第7位起.txt`。

**最硬的一组对照（2026-11-15 与 11-17，同一份程序、同一张桌子）**：

| | U4（11-15） | U5（11-17） |
|---|---|---|
| 遥测行数 | 7 | **2** |
| 启动次数 | 4 | **1** |
| 输入被拒 | 1 次（`amount=NaN`） | **0** |
| 落库笔数 | 2 笔 44 元（其中 27 元是他不要的） | **1 笔 15 元** |
| 从启动到记完 | 2 分 18 秒 | **27 秒** |

**一条必须写明的反例（2026-11-15，U4）**：作者口述"进去之后自己按下的 1，最后记成了，然后直接退出"，遥测却是 **4 次启动 + 1 次输入被拒 + 记成 2 笔**。作者事后说明了两件事：第一，那 3 次重开都是**访客自己**做的；第二，**`27` 元是输错的那笔，他真正想记的是 `17` 元**。也就是说：他先记错了一笔，菜单里改不掉，只能关掉重来；重来途中又输了一次非数字被拒；最后才记对。**这条差异完整保留在 `2026-11-15_U4.md` 第二节与 P12，不改口述、不粉饰遥测。**

**一条必须写明的干预（2026-11-15，U4）**：ITER-003 的判据写的是"同一句指令、全程不提示、不指屏幕"。实际执行时**访客在门口问了「点那个」，作者回答了**——按作者原话是"正常说，没有完全说，引导他去记录"。**因此 U4 不能记为"零提示下第一次点对"**，`ITER-003.md` 4.1 已按此降级为"待定"，H1 的裁决等第 2 位在完全无提示条件下测试的用户。宁可把已经到手的支持降级，也不能拿一条被干预过的记录当结论。

**一项已确认的补充（2026-11-14 22:39，作者本人回答）**：三人**都没有旁观过彼此操作**——「我找的人都没看过」。U3 是同班、不同宿舍，来之前没见过这个程序，54 秒是他第一次上手的时间。这条排除了"后面的人在旁边学会了再上手"这一最容易被质疑的污染路径。


## 三、如何补足"人的痕迹"（设备之外的部分）

同一台设备无法改变，但"是谁在用"可以由以下四样补足，**缺一样不计入**：

1. **日期**——哪天第一次用
2. **他自己的屏幕截图**——带任务栏时间
3. **他本人的原话**——逐字记录，不改写、不归纳
4. **遥测日志**——从 GENESIS 开始的那条链

**加分项（不强制）**：现场照一张，画面含操作者的手、屏幕、宿舍背景，不拍脸。这张能直接回答"是不是另一个人坐在那儿"。

**已落实**：U3（2026-11-14）拍摄了现场照 `2026-11-14_U3_3_现场照_手与屏幕.jpg`——画面里有操作者的手、屏幕上的程序界面、桌面环境。这是三次测试中的第一张，后续每位补一张。

## 四、已知局限（不隐瞒、不淡化）

| 局限 | 影响 | 处理 |
|---|---|---|
| 同一台设备 | 运行环境痕迹同源（同一 `node.exe`、同一路径） | 无法消除，只能用第一、二节说明 |
| 受访者集中在同宿舍、同班 | 样本代表性有限，不能外推到全校 | 报告中限定结论范围 |
| 均为一次性试用 | 不能证明留存意愿、不能证明长期可用性 | 不把"愿意继续用"写进结论；**U3、U7、U8 明确说不用（三人均记成，U8 仅 11.9 秒），8 人中 0 人表示愿意继续** |
| **受访者多为「平时不记账」的人** | **测出来的是"不记账的人会不会用记账工具"，不是"记账的人用得爽不爽"** | **剩 5 位中刻意找 1–2 位本来就在记账的人（微信记账本/Excel/纸条/支付宝账单都算），记录卡增加一栏"他平时用什么记"** |
| 存在同一晚连续试用 | 时间分布集中 | 后续用户尽量分散到不同日期 |

## 六、判断标准：什么算一个"真实用户"

**四项齐备即计入**：日期 / 本人屏幕截图 / 本人原话 / 本人用过（有从 GENESIS 开始的遥测日志）。

**不要求记账成功。** U2 记了 0 笔，四项齐备，计入，并如实标注「尝试后放弃」。

理由：考核要的是"8 位真实用户"，不是"8 位成功记账的用户"。**一个被第一步劝退的人，比一个被手把手带着做完的人，暴露的问题更多。**
